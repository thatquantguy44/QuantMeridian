# Market Terminal local services runbook

This is the canonical startup guide for a local Market Terminal environment. It distinguishes
the core processes required for database-backed terminal pages from optional companion services
that activate individual modules.

All examples assume the workspace layout below:

```text
Quant Sandbox/
├── fred-bronze-to-gold-pipeline/
├── QR-Haven/
└── platforms/
    └── market_terminal/
```

Do not `source` the entire Market Terminal `.env` file. Dotenv syntax is not guaranteed to be
valid shell syntax, particularly when a local path contains the `Quant Sandbox` space. Commands
below either let Vite load `.env` or load a single named variable.

## Service inventory

| Process | Required? | Port | Used by | Health check |
|---|---:|---:|---|---|
| Docker Desktop | For local PostgreSQL | n/a | Docker Compose | `docker info` |
| Gold PostgreSQL (`fred-pipeline-postgres`) | Core live-data path | `55432` | Market, macro, Data Ops, chart and related Gold routes | `docker compose ps` |
| Market Terminal | Required | `3000` | Browser UI and `/api/*` routes | `GET /api/dataops/health` |
| InventoryBallast API (IBAL) | Optional | `8013` | `/inventory-optimizer` | `GET /health` |
| QR Haven volatility API (VOLF) | Optional | `8000` | `/ml/volatility-forecaster` | `GET /health`, `/status` |
| News NLP | Optional | `8088` | NEWS/SENT FinBERT, NER and clustering tier | `GET /health` |

The minimum database-backed system is Docker Desktop, Gold PostgreSQL, and Market Terminal. IBAL,
VOLF, and News NLP can be started independently when their modules are needed.

## Prerequisites

- macOS with Docker Desktop and Docker Compose.
- Node.js 20 or newer and npm.
- Python 3.12 for InventoryBallast and the QR Haven model runtime.
- The sibling repositories shown in the workspace layout.

Check the basics:

```bash
docker info
node --version
python3.12 --version
```

If Docker is installed but its daemon is stopped:

```bash
open -a Docker
```

Wait for Docker Desktop to report that its engine is running before using `docker compose`.

## Startup order

### 1. Start Gold PostgreSQL

The canonical local warehouse is declared by the pipeline repository's Compose file. Its current
local contract is:

```text
host      127.0.0.1
port      55432
database  macro_medallion
username  fred
password  fred
```

Start it:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/fred-bronze-to-gold-pipeline"
docker compose up -d postgres
docker compose ps
```

The expected container is `fred-pipeline-postgres`, with status `healthy` and host port `55432`
mapped to container port `5432`. If Compose cannot reach the Docker daemon, start Docker Desktop
first. If this is a new empty volume, follow the pipeline repository's ingestion/publication
instructions to populate the `gold` schema; starting PostgreSQL does not itself ingest data.

Configure Market Terminal in its gitignored `.env`:

```dotenv
MACRO_DB_URL=postgresql://fred:fred@127.0.0.1:55432/macro_medallion
```

Do not set `MACRO_DB_BACKEND` for PostgreSQL. The terminal detects Postgres from the
`postgres://` or `postgresql://` prefix.

### 2. Start Market Terminal

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/platforms/market_terminal"
npm install                   # first checkout or dependency change only
unset MACRO_DB_URL            # prevents a stale exported shell value overriding .env
npm run dev
```

Open `http://127.0.0.1:3000`. Startup should include a message like:

```text
[goldStore:OK] MACRO_DB_URL configured properly (backend=postgres, host=127.0.0.1, database=macro_medallion)
```

Verify the aggregate service state:

```bash
curl -s http://127.0.0.1:3000/api/dataops/health | python3 -m json.tool
```

The message `[proxy] no proxy configured ... server fetch goes direct` is informational. It means
the Node server is making direct outbound HTTP requests; it does not describe the database
backend.

For a production-style local build instead of Vite:

```bash
npm run build
PORT=3000 HOST=127.0.0.1 npm start
```

The standalone `npm start` process does not load `.env` through Vite. Export the variables it
needs in that shell, or start it through an environment manager.

## Optional companion services

### InventoryBallast API (IBAL)

IBAL is a separate Python service because Market Terminal never imports or executes the optimizer
engine in the browser/Node process. The terminal and IBAL service must share the same bearer token.

Add a local token to Market Terminal's `.env`:

```dotenv
INVENTORY_OPTIMIZER_API_TOKEN=local-only-change-me
# INVENTORY_OPTIMIZER_API_URL=http://127.0.0.1:8013  # this is the default
```

For anything beyond loopback-only development, replace the example with a strong token such as
one generated by `openssl rand -hex 32`.

First-time service setup:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/platforms/market_terminal/services/inventory_optimizer_api"
python3.12 -m venv .venv
.venv/bin/pip install -e ".[dev,highs]"
```

The current service environment already contains the reviewed InventoryBallast engine. Prefer
that installed copy. Only set `INVENTORY_OPTIMIZER_ENGINE_PATH` when deliberately testing another
checkout; readiness rejects a checkout whose version, fingerprint, or commit differs from the
pin in `capability-manifest.json`.

Start IBAL:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/platforms/market_terminal/services/inventory_optimizer_api"
source <(grep '^INVENTORY_OPTIMIZER_API_TOKEN=' ../../.env)
.venv/bin/uvicorn inventory_optimizer_api.app:app --host 127.0.0.1 --port 8013
```

Verify it from another terminal:

```bash
curl -s http://127.0.0.1:8013/health | python3 -m json.tool
```

The response must show `"ready": true`, the reviewed engine commit, no `engine_mismatches`, and at
least one active solver backend. Restart Market Terminal after adding or changing the token, then
open `http://127.0.0.1:3000/inventory-optimizer`.

If browser solve POSTs hang under Vite while direct health checks work, use the documented
standalone-server verification path in `docs/features/IBAL_WHAT_IF_HANDOFF.md` and
`docs/features/IBAL_VITE_POST_HANG_INVESTIGATION.md`.

### QR Haven volatility API (VOLF)

VOLF displays QR Haven's five-session SPY realized-volatility forecast. These forecasts come from
the verified QR Haven model/report artifacts, not from `macro_medallion`. Market Terminal calls QR
Haven through its own server route so the service URL is not exposed to the browser.

Market Terminal defaults to `http://127.0.0.1:8000`; the optional explicit `.env` setting is:

```dotenv
QR_HAVEN_VOLATILITY_API_URL=http://127.0.0.1:8000
```

First-time QR Haven deployment setup:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/QR-Haven"
python3.12 -m venv .venv
.venv/bin/pip install -c infrastructure/volatility-api/runtime-constraints.txt -e ".[research,deployment]"
```

Start the API against the live shadow-report root:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/QR-Haven"
QR_HAVEN_SHADOW_ROOT="$PWD/artifacts/classification/volatility/tiingo-spy-v1/shadow/live-v1" \
PYTHONPATH=src \
.venv/bin/python -m uvicorn qr_haven.ml.volatility.deployment_api:create_app \
  --factory --host 127.0.0.1 --port 8000
```

Verify the model and report:

```bash
curl -s http://127.0.0.1:8000/health | python3 -m json.tool
curl -s http://127.0.0.1:8000/status | python3 -m json.tool
```

The terminal intentionally preserves QR Haven's `shadow_only` deployment status and
`target_not_met` research status. Open
`http://127.0.0.1:3000/ml/volatility-forecaster` after both services are running.

### News NLP

News NLP upgrades NEWS/SENT from the built-in heuristic tier to the optional FinBERT, NER, and
event-clustering service. Market Terminal remains usable without it.

First-time lightweight setup (lexicon fallback service):

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/platforms/market_terminal/news_nlp"
python3.12 -m venv .venv
.venv/bin/pip install -e .
```

For the full local model stack, install `-e ".[nlp]"` and then run
`.venv/bin/python -m spacy download en_core_web_sm`.

Configure Market Terminal:

```dotenv
NEWS_NLP_URL=http://127.0.0.1:8088
```

Start and verify the service:

```bash
cd "/Users/joshualutkemuller/Documents/Quant Sandbox/platforms/market_terminal/news_nlp"
.venv/bin/news-nlp serve --host 127.0.0.1 --port 8088

# From another terminal:
curl -s http://127.0.0.1:8088/health | python3 -m json.tool
```

Restart Market Terminal after adding `NEWS_NLP_URL`.

## Integrations that do not require a local service

- News providers (Alpha Vantage, Marketaux, Finnhub, NewsAPI) require server-side API keys only.
- Social providers require their documented tokens/user-agent settings only.
- Anthropic Copilot requires `ANTHROPIC_API_KEY`; no repo-owned local service is started.
- Cron cache warming is an external scheduler calling the terminal; it is not a local daemon.
- A configured OpenAI-compatible or Anthropic-compatible LLM gateway is externally operated.

The `services/agent_worker` directory is currently contract/settings scaffolding for spec009. Its
runtime and `npm run agent:worker` launcher are still marked TODO, so there is no supported worker
process to start yet. Do not invent a local startup command from the draft plan.

## Legacy services: do not start for the current architecture

The in-repository `market_data_pipeline/docker-compose.yml`, `MARKET_PIPELINE_URL`,
`MARKET_DB_URL`, and `MARKET_DATA_DIR` belong to the retired pre-Gold read path. Current market and
macro routes use `MACRO_DB_URL`. The legacy API also claims port `8000`, which conflicts with QR
Haven VOLF, so it should not be started as part of the normal local stack.

Direct FRED route access is also deprecated for production reads. `FRED_API_KEY` remains useful
only for documented offline export/refresh helpers.

## Shutdown and restart behavior

- Stop Market Terminal, IBAL, QR Haven, and News NLP with `Ctrl+C` in their terminals.
- Stop only local Gold PostgreSQL with:

  ```bash
  cd "/Users/joshualutkemuller/Documents/Quant Sandbox/fred-bronze-to-gold-pipeline"
  docker compose stop postgres
  ```

- `docker compose down` removes the container/network but preserves the named database volume.
  Do not add `-v` unless deleting the local database volume is explicitly intended.
- Any `.env` change requires restarting Market Terminal. Vite reads dotenv files at process
  startup, and a value already exported in the shell takes precedence over `.env`.

## Common failures

| Symptom | Cause | Resolution |
|---|---|---|
| `Cannot connect to the Docker daemon` | Docker Desktop is stopped | `open -a Docker`, wait for the engine, then run `docker info` |
| `npm ERR! ENOENT ... package.json` | `npm run dev` was run from the pipeline repository | `cd` to `platforms/market_terminal` first |
| Startup reports `backend=sqlite` | `.env` or an exported shell variable still contains a SQLite URL | Set the Postgres URL, `unset MACRO_DB_URL`, restart Vite |
| Postgres `ECONNREFUSED` on `55432` | Container is stopped or Docker is unavailable | Start Docker and `docker compose up -d postgres` |
| IBAL page says token missing | Terminal and service do not share a token, or Vite was not restarted | Set the same token in both processes and restart Market Terminal |
| IBAL health says `incompatible_engine` | An unreviewed checkout overrides the pinned engine | Remove/fix `INVENTORY_OPTIMIZER_ENGINE_PATH`; use the reviewed installed engine |
| VOLF shows disconnected | QR Haven API is not running or report root is wrong | Start port `8000` with the live shadow root; check `/health` and `/status` |
| NEWS remains heuristic/SIM | NLP service or upstream news keys are absent | Start News NLP and set `NEWS_NLP_URL`; configure a provider key for live headlines |
